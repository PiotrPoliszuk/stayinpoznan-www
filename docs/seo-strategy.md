# SEO strategy

## Positioning

The primary entity is **Stay in Poznań**, an independent short-stay apartment brand at **Wielka 23**, around 100 metres from Poznań Old Market Square.

The site targets intent clusters rather than repeating broad keywords:

1. property intent: `apartament Poznań Stary Rynek`, `nocleg Poznań centrum`;
2. location intent: `nocleg Stary Rynek Poznań`, `apartament z widokiem na Ratusz`;
3. event intent: `nocleg Pyrkon 2027`, `nocleg BitterSweet Poznań`, `nocleg MTP`;
4. planning intent: `weekend w Poznaniu`, `atrakcje Poznań Stary Rynek`;
5. international intent: `Poznań Old Town apartment`.

No one can honestly guarantee position 1 for broad accommodation queries dominated by Booking, Airbnb and large aggregators. The realistic route is to own high-conversion local and event queries, then build authority for broader phrases.

## Technical foundation

- static HTML with no render-blocking framework;
- unique title, description, canonical and one H1 per page;
- PL/EN hreflang for the home and apartment pages;
- indexable image URLs and descriptive alt text;
- XML sitemap and permissive robots.txt;
- breadcrumb and article structured data;
- VacationRental structured data for Koziołki View (eight authentic images);
- LodgingBusiness structured data for Ratusz View until an eighth authentic photo exists;
- noindex for the unfinished mezzanine apartment;
- permanent host redirects from `www` and `oldmarketsquare.pl`.
- campaign aliases on both domains that resolve with HTTP 301 to one canonical landing page.

## Content rules

- Event dates must come from the official organizer and show the verification date.
- Expired event pages should be updated to the next confirmed edition or retained as a useful archive; never silently change an unconfirmed date.
- Do not create near-duplicate pages by swapping only a keyword or year.
- Do not invent distances, amenities, reviews or availability.
- Apartment images must remain authentic. Illustrative city graphics must never pretend to show the real view.
- Review counts and ratings should be refreshed from the public listings before major releases.

## Work outside the repository

Code alone will not win local search. The launch checklist also needs:

- a verified Google Business Profile with consistent name, address and phone;
- Google Search Console and Bing Webmaster Tools;
- direct links from Airbnb/Booking host profiles where allowed;
- citations from local tourism, event and business directories;
- original guest reviews and current photos;
- useful partnerships/backlinks from Poznań guides and event communities;
- regular monitoring of impressions, clicks, queries and Core Web Vitals.

## 90-day content order

1. Launch the core site and request indexing of the home and two apartment pages.
2. Publish and internally link the currently confirmed event pages.
3. Add a genuine restaurant/café guide based on the hosts' own recommendations.
4. Add the mezzanine only after real photos, capacity and booking data exist.
5. Review Search Console queries after 28 and 60 days; improve pages already receiving impressions before creating more URLs.
